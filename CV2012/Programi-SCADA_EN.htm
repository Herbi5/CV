Central data acquisition system of spinning lines F and G (BARMAG)

TARGERT USER:

Julon d.d., Aquafil S.p.A.

DESCRIPTION:

Central data acquisition system allows monitoring and archiving numerous parameters of BARMAG spinning line (line F and G). It is designed on Ltg SCADA system and the OPC server (NT9100) by Johnson Controls. A dedicated software application was written in Visual Basic programming language to acquire data from Barmag control system. This application collects data from local databases provided by control system of spinning line and forwards them to the server application NT9100 through implementation of DDE. Central database system called DigiDB (part of Ltg SCADA) is linked to the OPC/DDE server/client application NT9100 and draws provided data from it. DigiDB stores each acquired value into its internal database file system. The heart monitoring is application DigiVent (also part of Ltg SCADA) that enables the user to visualize graphically the operational data and chart acquired parameters of the spinning line. The goal of central data collection was to store on a single location all the data available by spinning line and to allow line operator fast review and comparison of data by means of predefined charts, which original Barmag monitoring system does not provide.

Central data acquisition system from energy installations

TARGERT USER:

Julon d.d., Aquafil S.p.A.

DESCRIPTION:

Central data collection system of energy installations was designed to monitor and to archive key operational parameters of energy facilities (air-handling units, compressors, water treatment, heating system, etc..) and to store acquired data on a centralized location. On one hand, system allows preservation of historical data on operation of various energetic devices under the common database file structure and on the other hand, it enables the end-users a remote insight on the current operation and control over target energy installations. The OPC specification were selected to be preferred communication channel of data exchange between various devices, since most existing monitoring systems or SCADA servers support this way of data exchange. OPC in this moment is considered to be one of the key standards for interconnection and data exchange among the various devices. It is primarily used to merge applications of a higher level (SCADA) with low level applications - process management hardware. In our case OPC server (NT9100) was chosen to acquire data from remote device management systems (such as PLC) and/or SCADAs. OPC server/client application NT9100 collects data via OPC communication from the individual monitoring systems, monitoring dedicated computers and remote monitoring devices and transmits data to a central database application - DigiDB. Process monitoring in developed on the application DigiVent, which is commercially available SCADA custom built by Ltg Engineering. Main advantages of this SCADA are: it allows simple and rapid prototyping of user interface masks, the application is not robust and it does not require a powerful computer, it allows simultaneous connection more supervision computers while the license is not tied to the number of users nor to number of bytes exchanged, further more it includes a simple file system for archiving data that could be accesses with other applications allowing simple data processing. To accommodate the central data collection of energy facilities as required, the means of communication with the OPC server and target device had to be determined, target parameters had to be decided upon, cross-reference tables of data exchange between devices and the central computer had to be devised, and control masks allowing fast review and supervision of parameters had to be developed.
