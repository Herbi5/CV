Program for monitoring supervisory system (SCADA) data and alarming via SMS/EMAIL messages

TARGET USER:

Julon d.d., Aquafil S.p.A.

DESCRIPTION:

The programs are intended to notify (alarm) users about critical events via e-mail and/or SMS messages. Three different programs with a similar graphical interface and principle of operation forward, in real time, information on events registered by the Tracer Summit SCADA system from TRANE, the Super-Flash supervisory system and the RSView32 SCADA supervisory system from Rockwell Automation. The essential difference between the individual versions of the program is that each is built specifically for monitoring one type of SCADA system, since the sets of parameters as well as the databases differ from one another. The heart of the e-mail sending is therefore the Email/SMS server program, which monitors the data (parameters, trends) and events (alarms / system messages) of the individual central supervisory system. The Email/SMS server connects to the local database and the events database (ALARMS) that SCADA stores in real time on the local computer and, based on the information obtained, produces three types of messages: an event message (SCADA alarms), a message about exceeded parameter limits, and a system message intended for verifying communication to the users. The program then forwards the messages to the Ozeki SMS server in the case of short messages and/or to an SMTP Email server in the case of e-mail messages. Both SMS and Email messages are sent to all users who are defined as recipients in the configuration file. In addition to the events already defined by the supervisory system, the program allows defining custom parameter limits, which are distributed when the limit values are exceeded.

Program for remote monitoring of the BARMAG spinning plant


TARGET USER:

Julon d.d., Aquafil S.p.A.

DESCRIPTION:

The existing software for monitoring the BARMAG spinning line, which was supplied together with the hardware, is a typical SCADA whose primary purpose is monitoring and setting the parameters of the production process. A significant shortcoming of this program, apparent from the very first use, is that it provides no insight into the current utilization of the production line through a simple graphical display, on the basis of which the operator could quickly identify critical points and problems in the production process at any moment. The program only allows numerical data to be browsed by position, which is rather time-consuming for forming a true picture of what is happening on the production line and requires an operator well trained in data analysis and interpretation. To simplify and automate the data analysis procedures, the RPM program was developed. It is designed to connect in real time to the database on the central supervisory computer of the production process and to periodically collect data on breaks, stoppages, number of bobbins produced, winding time and product type for each position. The data obtained are used to calculate and evaluate the utilization of the production line by work shifts and time periods. The utilization of each position is plotted in real time as a line diagram, which allows the operator to quickly identify faults. Interruptions in the line diagram represent stoppages in the production process, while each individual doff is marked with a small dash. Numerical values are also printed for each position for easier and faster quantification of position efficiency. The RPM program allows simultaneous collection of data from several supervisory computers, each of which monitors individual subsystems that are part of a larger production line, and combines the data in a common database and a common display on the screen. Data can be plotted by systems, products or groups, as defined by the operator.

Program for remote monitoring of the climatic conditions of spinning plant C

TARGET USER:

Julon d.d., Aquafil S.p.A.

DESCRIPTION:

Monitoring the state of the climate in the spinning cabinets is of utmost importance for the final quality of the filament. The production process is organized so that the climate parameters are monitored and controlled by the energy technician on duty (HVAC technician) from a remote computer in the energy facility, which runs the dedicated Krantz climate control program. This program stores the history of the measured parameters locally on disk, which also allows the parameters to be reviewed later in the event of major deviations. Due to poor and delayed communication between the energy technician on duty and the process technologist on the spinning line, deviations of the climate parameters are reported late and action (segregation of material) is taken late, which increases the likelihood of customer complaints. To give the technologist on the spinning line an immediate view of the climatic conditions by system, a program was developed that enables monitoring and plotting of diagrams of all key climate operating parameters (temperature, humidity and pressure). The program connects in real time to the remote computer in the energy facility and periodically acquires the measured values. Based on the limit values defined for each system, the program automatically and instantly alerts the operator in the event of a deviation.

Program for central data collection of the spinning and winding sections of line C

TARGET USER:

Julon d.d., Aquafil S.p.A.

DESCRIPTION:

Spinning line C has two mutually separate and completely incompatible supervisory systems. The first, supplied by the manufacturer Toray, is used for monitoring and setting the drive section (godet drives, winder, etc.) of the production line. The second, developed at Aquafil and based on the SuperFlash SCADA program, is used for monitoring and controlling the spinning section (extruder temperatures and pressures, spinning beam, etc.). Both systems record and archive data in their own format. As a rule, the data are available only for a limited period (one month) and therefore do not allow looking back over a longer period. Because of the different record formats, it is also not possible to simultaneously compare and correlate parameters of the spinning section with those of the winding section. To preserve the parameters for a longer period, the diagrams are printed once a month (applies to the spinning section only) and stored in paper form. Thus, for the past period there is no digital record of the running (operation) of the spinning line. For this purpose the LineScan program was developed for simultaneous monitoring and recording of data from both of the above supervisory systems in a common database, which can be accessed quickly and which allows subsequent numerical processing and correlation of the signals.

Computer application for controlling operation of custom uniaxial tensile testing apparatus

TARGERT USER:

Center for Experimental Mechanics(CEM) - Master thesis

DESCRIPTION:

The computer application is designed to control the operation of custom built apparatus for uniaxial tensile testing of polymer samples in controlled environment.  It directly controls devices such as servomotor controller, thermostatic circulator over serial communication port RS232/RS485 and performs online measurements by utilizing data acquisition system acquiring measured data through HP-IB communication port. Data acquisition could be performed in linear or logarithmic timescale. Acquired data on temperature, uniaxial load, longitudinal extension and transverse contraction is used to calculate time-dependent tensile relaxation modulus and Poisson's ratio. Measured and calculated data is plotted on the screen and written into data files for further analyses.
